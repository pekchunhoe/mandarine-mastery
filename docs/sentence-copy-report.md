# 造句积木 — sentence copying and external prompt copying

26 October 2026, Asia/Kuala_Lumpur. Implemented locally; no commit, push or deployment.

## Existing feature audit

The activity already had **复制句子** for the student's draft and individual copy controls for hint/vocabulary reference arrays. Corrections, expansion levels, vivid rewrites and vocabulary usage sentences did not have equivalent controls. AI vocabulary cards could show the same generated example twice, once in dictionary details and once as contextual usage.

The guided-essay activity has an external-AI copy menu, but 造句积木 had no external prompt copier. Its shared `buildSentenceTeacherContext()` already supplies the committed target, mode, actual scenario, current draft and available year. The shared `copyText()` already prefers the Clipboard API and falls back to a temporary selected textarea. That fallback needed to stay inside an open native dialog because the rest of the page is inert.

## Individual sentence copying

Each validated structured model entry now has a one-click **📋 复制句子** control:

| AI action | Copyable output |
| --- | --- |
| 💡 给我提示 | Each reference example; a pattern entry also gets a control if it is a complete model rather than a blank scaffold. |
| 🔍 检查句子 | The corrected/suggested complete sentence. |
| 🌱 帮我扩写 | Each expansion level's model. |
| ✨ 写得更生动 | The improved model; a try-yourself entry also gets a control if it is already a complete model. |
| 📚 推荐好词 | Each recommendation's contextual usage, both final reference examples, and a distinct AI-supplemental example if it differs from the contextual usage. |

Existing reference-array copy buttons are reused. Identical dictionary/contextual AI examples are displayed once; distinct additional examples remain separately copyable. Authoritative library dictionary examples are not reclassified as AI models. Blank scaffolds, explanations, labels, headings and the student's original are not copied as generated examples.

Copy values come directly from the validated structured fields. No punctuation splitting is performed, so Chinese quotations, compound sentences, whitespace, Unicode and punctuation stay exactly as returned. Labels and button text never enter clipboard values. Copying never pastes into the editor, records learning progress, changes drafts or requests Gemini.

Controls are created only after the existing AI request succeeds and is validated. Rejected output receives no model-copy controls. The existing context fingerprint is checked again before copying, including when a scenario is changed programmatically without an input event.

## Five adjacent external prompt controls

Each existing Gemini button retains its action and receives a separate, visually secondary copy icon. Each icon has tooltip **复制提示词**, an action-specific screen-reader label, a native button role and an independent touch area of at least 44×44 pixels. The existing two-column/four-column responsive grid remains; the icon is a sibling of the Gemini button, not nested inside it. The icon uses the existing muted palette and a small copy SVG.

One click immediately copies the whole usable prompt. There is no menu, normal-copy modal, second confirmation or external-site launch. Copy icons stay available when Gemini is unavailable or cooling down. Copy events have separate selectors/handlers and cannot activate the adjacent Gemini action.

The same central context getter supplies both Gemini and external prompts. Copies reflect current scenario/draft/year edits and the committed highlighted target in both keyword modes. Unconfirmed custom keyword edits do not silently change the target. Block mode reads the current assembled sentence and existing editable scenario. Copying with an empty draft is supported: tasks that require a sentence explicitly ask the external AI to request an original rather than fabricate one. Missing scenarios also receive a clear instruction to ask for the intended situation.

## Actual prompts and readable output

The five complete, exact example prompts are saved in [sentence-copy-prompt-examples.md](sentence-copy-prompt-examples.md). They were generated by the production prompt builder using target **坚持**, the supplied long-run scenario, original **我坚持跑到了终点。**, and **Standard 3**. They match what the UI copies for that context and require no API call.

Each is independently usable and has its own task:

1. **给我提示**: situation, actions/feelings and development/outcome ideas; natural keyword use; two distinct relevant complete examples.
2. **检查句子**: exact keyword, grammar, naturalness and scenario fidelity; applicable strengths, concrete improvements and one complete corrected reference; no needless rewriting of a correct sentence.
3. **帮我扩写**: one complete expansion retaining the scenario and original meaning, followed by a short explanation of relevant additions.
4. **写得更生动**: one complete improvement preserving facts, with suitable verbs, feelings or sensory descriptions and a short explanation.
5. **推荐好词**: approximately 4–6 suitable words/expressions with meaning and scenario use, plus two complete examples using recommendations and the exact target.

Every prompt explicitly requests natural, readable Chinese with short Chinese headings and lists. Every prompt prohibits JSON, code, schemas/data structures, machine-readable formats and Markdown code fences, and does not request internal reasoning or system-prompt disclosure. The internal Gemini schemas, JSON handling, model routing, rate limits and retry behavior were not modified.

Common educational instructions require exact target characters and order in every complete model, natural word use, the actual student scenario, preserved people/places/events/causes/outcomes, concrete age-appropriate guidance and no generic unrelated story.

Only the intended keyword, scenario, current draft and available year are included. Unknown context properties, candidate IDs, unrelated student work, credentials, endpoints and private configuration are omitted. Student material is separated from teaching instructions with boundaries chosen to be absent from the material; its multiline text remains intact. Embedded commands cannot legitimately override the teaching instructions.

## Clipboard and state safety

Both features reuse `copyText()`. Native `navigator.clipboard.writeText()` is preferred. Rejected promises use the established selection fallback, now inside an open dialog when applicable. Fallback success is accepted only for an actual `true` result. Failure returns a friendly localized message, with no false success, permission request or automatic API call. Temporary fields are removed and focus restored.

Prompt-copy pointer handling keeps an active editing input focused, preserving Chinese composition input identity. Existing keyword/scenario input elements are not replaced. Keyboard users can Tab directly from each Gemini action to its copy icon and activate it with Enter. Success uses a brief toast; failures use the existing toast system.

Full-state browser snapshots verify unchanged drafts, scenarios, self-checks, XP, records, routes and browser history after copying. Mode changes, block redraws and reloads retain one live handler per icon. No additional persistence state or dependency was introduced.

## Remaining limitations

External AI responses are outside this app's server/browser validation. The copied prompts strongly request keyword inclusion and scenario fidelity but cannot guarantee an external model follows them. Live external-AI quality was not tested.

Layout and composition tests use Chromium/Edge with emulated viewports and synthetic Chinese composition events. Physical phone/tablet IMEs and native iOS/iPadOS clipboard behavior were not tested. Browsers can deny both clipboard methods; in that case the app reports failure and preserves the student's work.
