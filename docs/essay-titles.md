# Essay title database

`data/Mandarin_Essay_Master_1000_Titles.xlsx` is the only maintainable source for essay titles and model essays. Do not manually edit `data/essay-titles.json` or `data/essay-contents.json`: both are generated by the importer. The workbook has two required worksheets.

`EssayTitles` has one row per permanent `id` and 18 columns:

`id`, `title`, `title_pinyin`, `grade`, `category`, `theme`, `essay_type`, `difficulty`, `description`, `suggested_keywords`, `suggested_phrases`, `writing_guidance`, `activity_tags`, `min_words`, `max_words`, `active`, `sort_order`, `notes`.

`EssayContents` has one row per permanent `content_id` and these columns:

`content_id`, `essay_id`, `content_title`, `content`, `word_count`, `level`, `version`, `active`, `sort_order`, `notes`.

`essay_id` must exactly match an existing permanent `EssayTitles.id`. The current master catalogue requires exactly one active model per active title. Never link by row number or title text. `content_title` is optional, but `content`, `level`, `version`, and `active` are required. `grade` and `level` are the actual Standard, 1–6. Keep existing IDs permanent and never reuse an ID.

The workbook's `word_count` counts Han characters, excluding punctuation and whitespace. Import preserves this supplied value and records an independent `hanCharacterCount`; discrepancies appear in `test-results/essay-title-import-report.json`. Notes are preserved as metadata, including references to segmented words or length recommendations; they do not become global import limits. There is no whitespace-based Chinese word counting or essay rewriting. Only CRLF/CR line endings normalize to LF; leading/trailing text, punctuation and paragraphs remain intact.

The current workbook contains 1,000 unique titles and 1,000 unique content IDs, all active: Standard 1: 100; Standard 2: 140; Standard 3: 180; Standard 4: 190; Standard 5: 190; Standard 6: 200. The importer and build validate this distribution, relationships, grade consistency and one active model per title. Blank pinyin, keywords, phrases, descriptions and source guidance remain empty.

Edit the workbook, then run:

```sh
npm run essays:update
npm test
npm run build
```

For the full import, test and build sequence in one command, run `npm run essays:release`.

The importer validates both worksheets, required columns, IDs, title records, content records, relationships, active values, numeric fields, formulas, malformed rows, and Unicode before replacing either runtime dataset. It saves both previous runtime files in `docs/essay-title-backups/`. If an update would remove more than 25 records or more than 10% of either library, it stops and lists the affected title/content IDs. After review, use `npm run essays:update -- --allow-removals` only for intentional removals.

Only active records are shown to students. `sort_order` controls display order; if it is blank, IDs provide a stable fallback order. The runtime services in `js/essay-title-service.js` and `js/essay-content-service.js` provide title and model-essay lookup/filter APIs to writing activities.

## Student learning activities

`范文学习` reads `EssayTitles.id → EssayContents.essay_id`, selecting the stable `contentId`. It reads the full generated model essay in its original paragraphs, with existing sentence speech, highlighting, auto-scroll, and vocabulary support. Switching essays cancels playback. It uses local paragraph labels, short key points and a representative sentence; it never changes the source essay.

`要点导写` uses the same ID lookup and exposes all 1,000 titles through its existing filters and search. The editor starts with pupil writing only. Learners request help progressively and reveal the full 范文 with the existing explicit action. Local scaffolding is labelled; 700 titles have no source guidance or keywords. Genre-aware questions, paragraph roles, starters and checklists avoid imposing narrative structure on letters, speeches, diaries and descriptive/expository writing. AI actions and external prompt-copy actions receive the selected title's actual Standard and essay type alongside the unchanged pupil context; importing and displaying data make no AI calls.

`essay`, `paragraphBuilder`, `planner`, and `assistant` in `activities/writing.js` use central titles, grade/category/search filters, and model essays joined by stable essay ID. Their local plan labels adapt to the genre. Vocabulary recommendations continue using the central vocabulary library and the selected title's Standard. `treasure` only uses the central “帮助别人” category to find an existing vocabulary topic; it does not consume model essays. The vocabulary/settings UI uses the same central title service for topic options. Story Chain and sentence activities keep their independent content.

## Draft compatibility

All 300 previous title IDs and all 300 previous content IDs survive this update. Guided saves retain `guided-essay:<contentId>` keys; a changed model paragraph count never truncates saved pupil lines. Extra pupil paragraphs remain editable. Selected title IDs persist per activity in `essaySelections`, independently of filter results.

Older writing activities used `composition:<grade>:<lesson>:<index-or-title>` or `paragraph:...` keys, which could collide across filter positions and activities. New keys are `<activityId>:<grade>:<lesson>:<essayId>`. `js/essay-draft-service.js` copies a compatible old draft using its saved essay ID, or its unique saved title metadata when the old save lacks an ID. It never migrates using an array position. Originals remain intact, new keys take precedence on subsequent loads, and each activity receives its own copy. Unmatched/custom-title drafts stay in storage and remain available in the teacher's draft review and full state export. No storage clearing or destructive migration occurs.

## Adding a model essay

1. Open `data/Mandarin_Essay_Master_1000_Titles.xlsx`, then the `EssayContents` worksheet.
2. Add one row with a permanent, unique `content_id`.
3. Enter the matching permanent `EssayTitles.id` in `essay_id`.
4. Paste or write the full model essay in `content`, set `active` to `TRUE`, and choose `level`, `version`, and `sort_order`.
5. Save the workbook and run `npm run essays:release` (or `npm run essays:update` during editing).

Do not manually edit generated JSON, reuse content IDs, or change existing essay/title IDs. The master catalogue must keep one active model essay per active title; inactive variants may be handled by the generic service, but the current master distribution expects 1,000 total content records.

`npm run build` verifies both JSON datasets against the actual workbook and fails with the regeneration command if they are stale. It copies both datasets into `dist/data/`, excludes source workbooks, and includes the JSON assets in the generated Service Worker list. Dataset bytes contribute to the content-hashed cache name and `version.json`. The existing update notice and user-initiated reload flow remain intact; no forced reload or localStorage clearing was added.

For browser integration coverage with the local server running: `npm run test:essay-browser`. See `docs/essay-master-integration.md` for the audited discrepancy and completed verification.
