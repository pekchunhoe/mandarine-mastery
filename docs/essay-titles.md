# Essay title database

`data/master-essay-titles.xlsx` is the only maintainable source for essay titles and model essays. Do not manually edit `data/essay-titles.json` or `data/essay-contents.json`: both are generated by the importer. The workbook has two required worksheets.

`EssayTitles` has one row per permanent `id` and 18 columns:

`id`, `title`, `title_pinyin`, `grade`, `category`, `theme`, `essay_type`, `difficulty`, `description`, `suggested_keywords`, `suggested_phrases`, `writing_guidance`, `activity_tags`, `min_words`, `max_words`, `active`, `sort_order`, `notes`.

`EssayContents` has one row per permanent `content_id` and these columns:

`content_id`, `essay_id`, `content_title`, `content`, `word_count`, `level`, `version`, `active`, `sort_order`, `notes`.

`essay_id` must exactly match an existing permanent `EssayTitles.id`; it is the relationship between one title and zero, one, or many model essays. Never link by row number or title text. `content_title` is optional, but `content`, `level`, `version`, and `active` are required. Keep existing IDs permanent and never reuse an ID.

The importer calculates `word_count` from Chinese characters, letters, and numbers, excluding whitespace and ordinary punctuation. A supplied count is normalized to that calculation and reported when it differs. The recommended model-essay length is 200–400 counted characters; 150–199 and 401–600 are allowed with a warning. Paragraph line breaks and Chinese punctuation are preserved.

Edit the workbook, then run:

```sh
npm run essays:update
npm test
npm run build
```

For the full import, test and build sequence in one command, run `npm run essays:release`.

The importer validates both worksheets, required columns, IDs, title records, content records, relationships, active values, numeric fields, formulas, malformed rows, and Unicode before replacing either runtime dataset. It saves both previous runtime files in `docs/essay-title-backups/`. If an update would remove more than 25 records or more than 10% of either library, it stops and lists the affected title/content IDs. After review, use `npm run essays:update -- --allow-removals` only for intentional removals.

Only active records are shown to students. `sort_order` controls display order; if it is blank, IDs provide a stable fallback order. The runtime services in `js/essay-title-service.js` and `js/essay-content-service.js` provide title and model-essay lookup/filter APIs to writing activities.

## Student learning activities

`范文学习` reads the generated model essay in its original paragraphs. It uses runtime-derived paragraph labels, short key points, a representative sentence, and vocabulary matches from the existing vocabulary library; it never changes the source essay.

`要点导写` deliberately starts with the title, writing questions, keywords, and short key points. Learners request help progressively (keywords → points → sentence cue → example sentence), write one paragraph at a time, and only reveal the full reference essay for comparison afterwards. The derivation lives in `js/essay-training-service.js`, so no essay-specific clues are manually maintained.

## Adding a model essay

1. Open `data/master-essay-titles.xlsx`, then the `EssayContents` worksheet.
2. Add one row with a permanent, unique `content_id`.
3. Enter the matching permanent `EssayTitles.id` in `essay_id`.
4. Paste or write the full model essay in `content`, set `active` to `TRUE`, and choose `level`, `version`, and `sort_order`.
5. Save the workbook and run `npm run essays:release` (or `npm run essays:update` during editing).

Do not manually edit generated JSON, reuse content IDs, or change existing essay/title IDs. Multiple model essays may intentionally use the same `essay_id`.

`npm run build` automatically copies both generated datasets into `dist/data/`; never manually copy essay JSON files into `dist`.
