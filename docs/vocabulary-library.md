# Maintaining the central vocabulary library

The permanent human-editable master is **`data/master-vocabulary.xlsx`**. Teachers edit this workbook; `npm run vocabulary:update` validates and normalizes it into the generated runtime dataset **`data/vocabulary.json`**. All vocabulary-based activities receive the JSON records through `js/vocabulary-service.js` and the shared session/state layer. There is no backend, paid service, or deployment API.

## Everyday teacher workflow

1. Open `data/master-vocabulary.xlsx` in Excel.
2. Add or edit one word per row. Keep existing IDs. For new rows, leave `id` blank; fill `word` and `grade`.
3. Save the workbook and run:

   ```sh
   npm run vocabulary:update
   ```

4. Review the validation summary and `test-results/vocabulary-import-report.json`. The command ignores completely blank rows and refuses to replace `data/vocabulary.json` if it finds invalid, incomplete, or duplicate records. It also blocks a replacement that would remove more than 25 records or more than 10% of the library, listing the affected IDs. Only for a deliberate large deletion, use:

   ```sh
   npm run vocabulary:update -- --allow-removals
   ```

   This override disables only the large-removal guard; it does not bypass workbook or row validation.
5. Run `npm test` and `npm run build`, then check the app. Commit both `data/master-vocabulary.xlsx` and `data/vocabulary.json`.

`data/vocabulary.json` is generated runtime data. Do not normally hand-edit it. `dist/data/vocabulary.json` is generated by the build and should not be hand-edited either. The source-only master workbook is excluded from `dist`.

## Advanced one-off imports

1. Open `templates/vocabulary-template.csv` in Excel (choose **UTF-8** when opening CSV), or export the existing library as XLSX from **老师工具箱 → 管理词语库**. Save your master as `.xlsx`.
2. Add one word per row. Keep existing IDs. For new rows, leave `id` blank; fill `word` and `grade`. Add natural examples and essay topics where available.
3. Install dependencies once, from this project folder: `npm ci`.
4. Preview the workbook:

   ```sh
   npm run import-vocabulary -- "D:\path\MasterVocabulary.xlsx"
   ```

5. Review the printed counts and `test-results/vocabulary-import-report.json`. It contains every sheet/row, normalized record, error and warning. The command above changes no vocabulary.
6. Fix problems in Excel and preview again. Then write the reviewed rows:

   ```sh
   npm run import-vocabulary -- "D:\path\MasterVocabulary.xlsx" --write
   ```

   Default: merge, skip existing words. To update existing metadata:

   ```sh
   npm run import-vocabulary -- "D:\path\MasterVocabulary.xlsx" --write --duplicates=update
   ```

7. Check the result:

   ```sh
   npm test
   npm run build
   npm run dev
   ```

   Open `http://localhost:4173`, select the new year/filters, and try recognition, sentence practice and essay topics. Automated browser commands are `npm run test:browser`, `npm run test:extended`, and `npm run test:vocabulary-browser` while the server is running.

8. For normal publishing, commit both `data/master-vocabulary.xlsx` and the updated `data/vocabulary.json` in your deployment repository and deploy to Vercel. Use Framework **Other**, Build **`npm run build`**, Output **`dist`**, no environment variables. The current workspace did not contain a `.git` repository; connect/copy it to your actual Git/Vercel project before committing.

The original `npm run import:vocabulary` command remains an alias. XLSX, traditional binary XLS, CSV UTF-8, and exported JSON are accepted. Every nonempty workbook sheet must contain vocabulary headings; remove instruction sheets before import. The old source workbook layout (`生字`, `词语1`–`词语3`, `参考造句1`–`参考造句3`, optional `课次`) remains supported on year-named sheets.

## Columns and normalization

`generatedSynonyms` and `definitionChinese` are optional text columns in the existing `Vocabulary` worksheet. They remain strings in the generated JSON; Chinese punctuation is preserved. Keep the existing `synonyms` list column as well. Missing optional reference fields display `—`.

The main 词语库 and the in-place 词语库 dialog in 要点导写 both use `vocabularyService.searchWords()` and `components/vocabulary-details.js`. Search prioritizes exact words, word prefixes/substrings, generated synonyms, pinyin, Chinese definitions, then existing metadata. It supports Chinese substrings and case/tone-insensitive Latin text. The modal searches the full central library, independently of the activity's selected grade; the main library retains its existing filters.

The writing lookup opens the existing native dialog without changing the route or rebuilding the activity. It supports ×, Escape, keyboard focus wrapping, focus return, internal result scrolling, and visual-viewport resizing. It never inserts or replaces draft text. Dialog listeners are removed on close or activity disposal.

Run `npm run test:vocabulary-dialog` with the local server running after `npm run build` to check shared search, production-data equality, speech dispatch, draft preservation, keyboard use, and representative viewports. Speech dispatch uses controlled Mandarin/Cantonese test voices; viewport automation simulates reduced keyboard space and does not claim a physical-device keyboard test.

Required teacher input: **word**, **grade**. Every saved record also has **id**; blank IDs are generated automatically.

| English heading | Chinese heading | Values                                                    |
| --------------- | --------------- | --------------------------------------------------------- |
| id              | 编号            | Stable text; retain on export/reimport                    |
| word            | 词语            | Chinese word; outer whitespace trimmed                    |
| grade           | 年级            | 1–6; `3`, `Year 3`, `Tahun 3`, `三年级`, `3年级` accepted |
| pinyin          | 拼音            | Tone-marked text supported                                |
| meaningEnglish  | 英文意思        | Optional text                                             |
| meaningMalay    | 马来文意思      | Optional text                                             |
| partOfSpeech    | 词性            | Optional noun/verb/adjective or teacher terminology       |
| category        | 类别            | One category                                              |
| difficulty      | 难度            | Blank, 1 (easy), 2 (medium), 3 (hard)                     |
| exampleSentence | 例句 / 参考造句 | Preserved verbatim, including punctuation and line breaks |
| sentencePinyin  | 例句拼音        | Optional text                                             |
| synonyms        | 近义词          | List                                                      |
| antonyms        | 反义词          | List                                                      |
| collocations    | 搭配            | List of useful combinations                               |
| essayTopics     | 作文主题        | List; links vocabulary to an existing central essay title |
| tags            | 标签            | List                                                      |
| source          | 来源            | Teacher/source attribution                                |
| character       | 生字            | Optional original source character; must occur in word    |
| lesson          | 课次            | Optional text                                             |

Lists accept semicolons (`学校;阅读`), Chinese semicolons, `|`, `、`, newlines, or JSON string arrays. Use JSON arrays when an individual value itself contains those delimiters. Exports use JSON arrays for lossless round trips. Commas are preserved inside text. Entirely empty rows are ignored. No pinyin, translation, difficulty or example is invented when omitted. Difficulty is separate from the activity's existing easy/medium/hard scaffolding setting.

CSV exports include a `_csvEscapedFields` column to safely preserve text beginning with spreadsheet formula characters. Keep this column when reimporting an exported CSV; the importer restores the exact original text. XLSX writes these values as text. Formula cells in imported workbooks are rejected: paste their results as values first. Password-protected, unsupported or malformed workbooks show errors. Maximum import file size: 25 MB; maximum sheet length: 50,000 rows. Use batches for larger files. All normal student lessons load JSON, never Excel.

## Stable IDs and duplicates

- Existing 564 IDs (such as `3-巨-巨大`) are unchanged. Sorting, filters and pagination do not affect identity.
- New IDs encode year, Unicode word code points and optional source character. They are deterministic, independent of row position and stable across repeated imports. Save/export generated IDs back into your master workbook.
- Same **word + grade** is normally an existing record. The same word in another grade is allowed and flagged for information.
- Original same-year relationships with distinct source characters remain separate. To update an ambiguous word such as Year 3 `钥匙`, specify its original ID or source character.
- An ID attached to a different word/year is rejected. A word/year with a conflicting explicit ID is rejected rather than silently changing progress references.
- Repeated IDs or word/year/source relationships within a file are reported; the first valid row wins and later duplicate rows are excluded. Review errors before confirmation.
- Update merges supplied columns only: an omitted column retains existing metadata; an explicitly blank cell clears that field. Use skip (default) when you only want to add words.
- Replace uses only valid normalized input rows, including those identified as existing. The existing-word skip/update selector is inapplicable to replacement.

## Teacher browser workflow and backups

Open **老师工具箱 → 管理词语库** (also linked from the student library). Search, combine filters, change sort order, and page through 25 rows at a time. Add/edit records through the form; deletion requires confirmation. Import Excel/CSV/JSON, inspect the paginated preview, optionally show only problematic rows, select merge/update/skip, and explicitly confirm. Replacement has a second confirmation showing the affected counts. Cancel leaves the library untouched.

Browser changes persist in **IndexedDB `huawen-vocabulary`**, separate from student progress in localStorage `huawen-lab-v1`. They are local to this device/browser/origin. They do **not** modify project JSON or the Vercel deployment. The browser stores additions/overrides/deletion IDs over the bundled dataset, so newly deployed words can still appear alongside local edits. Local overrides win until you restore the published library. Export first before clearing browser storage.

Export JSON for a full backup; CSV and XLSX also retain every supported field and ID. Restore through the same preview/import interface. **恢复发布词库** clears local vocabulary edits after confirmation; student progress is untouched. Browser storage failures are reported and no successful save is claimed. There is no authentication; this remains a supervised teacher tool, like the existing teacher mode.

To publish a browser-edited library, export JSON, preview it using the command above, then merge/update into project data. To publish deletions too, explicitly replace the project library:

```sh
npm run import-vocabulary -- "D:\path\vocabulary.json"
npm run import-vocabulary -- "D:\path\vocabulary.json" --write --mode=replace --confirm-replace
npm test
npm run build
```

Every CLI write creates a timestamped previous dataset under `docs/vocabulary-backups/`, outside deployment assets. The CLI refuses writes with duplicate/invalid/incomplete rows unless `--allow-invalid` is explicitly supplied. It refuses empty replacement. To restore a backup, preview and explicitly replace with that backup file. A temporary file and rename avoid partially written canonical JSON.

## Activity behavior and data preservation

The same shared filtered pool feeds all 23 existing activity choices: recognition/timed recognition, matching, detective/cloze, memory, phrase and paragraph ordering, sentence builder/expansion/upgrade/doctor, multiple contexts/scenes/classification/relationships, paragraph builder, essay/planner/assistant, connectors, story and treasure. Word cards, review, weak words, favorites and the daily route also use the service-backed state.

Curated exercise prompts, grammar explanations, distractors and reviewed sentence chunks remain in teaching content. These are authored exercises, not alternate vocabulary libraries. New words can always use recognition and independent sentence/writing practice. Activities requiring an example use an explicitly labelled independent-writing alternative when the example is missing or does not contain the target. Reviewed multi-choice distractors and scene exercises are not fabricated for unannotated words. Connector grammar exercises retain their existing reviewed prompts and do not award word-specific mastery for unrelated grammar answers.

Essay suggestions use **essayTopics** as vocabulary relevance metadata, never arbitrary fallback words. Add an exact title from `master-essay-titles.xlsx` to a vocabulary record when it is relevant; this does not create a new essay title. The writing selector itself is generated only from the centralized essay-title database. Collocations, synonyms and antonyms are stored centrally for teaching assistance.

Migration retained **564/564 records**, **188 source-character relationships**, **237 Year 3**, **327 Year 4**, all IDs and original examples. The initial corpus is still Year 3–4; Years 1, 2, 5 and 6 await teacher-supplied vocabulary. `docs/archive/vocabulary-original.json` and `docs/archive/content-original.js` are audit-only snapshots, excluded from deployment and never used by the app. Original category, tag, topic and collocation memberships were moved into central records. The twelve pre-existing labelled teaching examples remain alongside the original sentences. No artificial sentences were added.

## Architecture and dependency

```text
data/master-vocabulary.xlsx → vocabulary-file.js → vocabulary-schema.js
                                                ↓ validation / normalization
                                    data/vocabulary.json (generated runtime data)
                                                ↓ + IndexedDB edits (local)
                                    vocabulary-service.js
                                                ↓
                                shared state / session → activities
```

The service exposes lookup by ID, year, category, difficulty, tag and essay topic, combined filtering, multilingual/accent-insensitive search, and random sampling. It indexes common fields once and precomputes searchable text. Excel parsing and large CSV parsing/validation run in a Web Worker in the teacher UI. Both library and preview DOMs are paginated. Student progress, scores, drafts, favorites and existing IDs are retained.

One dependency was added: **SheetJS CE 0.20.3**, pinned to its official distribution, for XLSX/XLS parsing and XLSX export. See [SheetJS installation documentation](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/). `tools/prepare-vocabulary.mjs` copies its ES module and license to local static assets; no CDN is contacted by students. The production build includes the new modules, template and parser in the content-versioned offline cache. No backend or Excel installation is needed.
